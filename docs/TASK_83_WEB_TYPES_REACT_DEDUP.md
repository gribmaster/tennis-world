# TASK 83 — `@tennis/web` build fails on Vercel: two copies of `@types/react` in the workspace

**Model: Sonnet 5, reasoning effort: high.** This blocks production deploys of the web app, so it is the top priority. Diagnose first, then fix with the smallest change. Do not guess: every claim in your report needs command output.

## Symptom (reproduced on Vercel, a clean `pnpm install --frozen-lockfile` from the committed lockfile)

`pnpm --filter @tennis/web build` → `next build` compiles, then fails in "Linting and checking validity of types":

```
./src/app/billing/return/page.tsx:50:10
Type error: 'Suspense' cannot be used as a JSX component.
  Its type 'ExoticComponent<SuspenseProps>' is not a valid JSX element type.
  ...
  Type 'import(".../node_modules/.pnpm/@types+react@19.2.17/node_modules/@types/react/index").ReactNode'
  is not assignable to type 'React.ReactNode'.
    Type 'ReactElement<...>' is not assignable to type 'ReactNode'.
      Property 'children' is missing in type 'ReactElement<unknown, ...>' but required in type 'ReactPortal'.
```

The `ReactPortal.children` requirement is the React 18 type shape; the `@types/react@19.2.17` copy is the one `apps/web` declares. So two different `@types/react` versions are being resolved inside one TypeScript program. `pnpm typecheck` for `@tennis/web` has been failing the same way on the owner's Windows machine since the admin app was added (it passed before). It passes on at least one Linux checkout, so it depends on the installed layout, not on the source.

## What we know

- `apps/admin` pins **React 18.3 / `@types/react@^18.3.31` / `@types/react-dom@^18.3.7`** (antd 5 + Refine). `apps/web` uses **React 19 / `@types/react@^19.0.2`**. The lockfile contains both `@types/react@18.3.31` and `@types/react@19.2.17`. Before TASK_74 only 19.x existed.
- CLAUDE.md §12: **React 18.3 stays pinned in `apps/admin`; MUST NOT change `apps/web`'s React version "to fix" this**. Those two constraints are fixed.
- The likely mechanism (confirm it, don't assume): a package in the `apps/web` TypeScript program (`next`'s own `.d.ts`, `@types/react-dom`, or a workspace package such as `packages/contracts`/`packages/mock-data` imported as source via `transpilePackages`) resolves `react` types through pnpm's **private hoist** (`node_modules/.pnpm/node_modules/@types/react`) or its own `node_modules`, and gets the 18.3.31 copy that the admin app introduced.

3. **Fix at the root cause, smallest change, in this order of preference** (stop at the first that makes both builds clean on a clean install; explain why you rejected the earlier ones):
